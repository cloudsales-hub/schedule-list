# 일정·할일 위젯 앱 — 설계 문서

작성일: 2026-11-20 / 상태: **승인 대기**

## 1. 의도와 이유

사용자는 업무량이 많고 종류가 다양해서 일정과 할일이 흩어지고 자주 놓친다. 특히 일하다가 전화를 받거나 누군가에게 요청을 듣는 등 **끼어든 일**을 잠깐 적어 두었다가 잊지 않고 나중에 처리하고 싶어 한다.

그래서 이 앱의 핵심은 두 가지다.

1. **적는 속도:** 하던 일을 끊지 않고 3초 안에 적고 돌아간다.
2. **보는 노력 0:** 프로그램을 열지 않아도 바탕화면에서 바로 보인다.

사용자는 윈도우 노트북과 데스크톱을 쓰고, 프로그래밍 경험이 전혀 없다. 코딩은 전부 Claude가 맡는다. 네이버 웍스 등 기존 도구와는 연동하지 않는다. 메모장처럼 적으면 캘린더와 업무 관리로 정리해서 보여주는 개인용 도구다.

## 2. 목표 / 비목표 / 실패로 보는 경우

**목표**
- 단축키 한 번으로 한 줄 메모를 입력하고 저장한다.
- 바탕화면 위젯에서 "급한 할일"을 마감 임박 순으로 항상 보여준다.
- 위젯을 클릭하면 노션처럼 한 화면에 모아 보는 대시보드가 열린다.
- 노트북과 데스크톱에서 같은 목록이 보인다.

**비목표**
- 네이버 웍스, 구글 캘린더 등 외부 서비스 연동
- 여러 사용자 공유, 팀 협업, 로그인, 서버 운영
- 모바일 앱
- 완료 기록 보관과 통계 화면 (최근 완료 카드는 사용자가 뺐다)
- `Win+L` 잠금 화면 자체를 바꾸거나 그 위에 화면을 표시하는 것 (윈도우 제약으로 불가)
- 날씨, 목표 관리, 우선순위·상태 열, 포스트잇 메모지 (사진은 참고용이고 사용자가 요청한 기능만 만든다. 나중에 사용자가 추가를 요청한다)

**실패로 보는 경우 (기술적으로 동작해도)**
- 입력하는 데 클릭이 여러 번 필요하거나 창이 하던 작업을 가린다.
- 위젯이 다른 창 위에 떠서 업무를 방해한다.
- 한쪽 컴퓨터에서 적은 메모가 다른 쪽에서 사라지거나 덮어써진다.
- 설치와 업데이트가 사용자에게 개발 지식을 요구한다.

## 3. 사용자가 확정한 내용

### 3.1 입력창
- 전역 단축키를 누르면 화면 중앙에 작은 입력창이 뜬다. **기본값은 `Win+J`** (사용자 선택)이고, 설정에서 사용자가 키 조합을 직접 눌러 바꿀 수 있다. 사용자는 `Win`이나 `Alt`를 섞은 2키 조합을 선호한다. 대안 후보는 `Alt`+`₩` 키(한글 키보드의 `Esc` 아래 키)이다. (`Win+M`은 윈도우의 "모든 창 최소화"라 사용 불가)
- 앱 시작 시 단축키 등록을 시도하고, 다른 프로그램이 이미 쓰는 키라 실패하면 "이미 사용 중인 키입니다"라고 알려주고 다른 키를 고르게 한다.
- 위젯 오른쪽 위의 `＋ 메모` 버튼(테두리가 있는 버튼 모양, 안에 단축키 표시)을 마우스로 눌러도 같은 입력창이 열린다.
- **메모 입력칸:** 위젯 맨 위와 대시보드 오른쪽 위에 한 줄 입력칸이 있어서, 대시보드를 열지 않고 바탕화면에서 바로 적고 `Enter`로 등록한다. `Win+J` 입력창과 같은 해석(미리보기, 일정/할일 구분)을 쓴다. 사용자가 포스트잇 메모지 대신 이 입력칸을 원했다.
- 한 줄을 쓰고 `Enter`를 치면 저장되고 창이 닫힌다. `Esc`는 취소다.
- 문장에 날짜나 시간이 있으면 읽어내서 마감으로 저장하고, 입력창에 인식 결과를 미리 보여준다. (예: "내일 오전까지" → 11/21 오전)
- 기한 표현이 없으면 마감 없는 **할일**로 저장한다.
- 사용자는 기한이 있는 메모와 없는 메모가 대략 반반이라고 했다.

### 3.2 바탕화면 위젯 (시안 A, 목록형)
- 항상 바탕화면 쪽에 떠 있고, 다른 창 아래에 깔린다.
- 위쪽에 **급한 것**(마감이 있는 할일)을 마감 임박 순으로 보여준다.
- 그 아래에 **할일**(마감 없는 목록)을 보여준다. 이름은 "나중에 할 일"이 아니라 "할일"이다.
- **일정 구간은 위젯에 넣지 않는다.**
- 체크하면 완료 처리되어 목록에서 사라진다.
- 위젯을 클릭하면 대시보드가 열린다.
- 위젯은 항상 다른 창 **아래**에 깔려서 업무를 가리거나 방해하지 않는다. 가려졌을 때는 `Win+D`(바탕화면 보기)로 보고, 트레이 아이콘을 눌러 위젯을 잠깐 맨 앞으로 불러오는 기능도 넣는 것을 제안한다. (사용자가 이 기능을 확정한 것은 아니다.)

### 3.3 대시보드 (위젯을 클릭하면 크게 열림)
- **달력:** 월 단위, 일정과 마감이 있는 날에 점 표시, 오늘 강조
- **오늘 / 임박 (중요 할일):** 마감이 오늘이거나 임박한 할일만 마감 순으로 보여준다. 일정은 여기 섞지 않는다.
- **일정:** 시간이 정해진 약속(회의, 통화 등)만 따로 보여준다. 중요 할일과 일정은 아예 별도 카드로 나눈다.
- **할일:** 마감 없는 목록
- "최근 완료" 카드는 없다.
- 맨 위에 큰 배너(기본 높이 320px)와 제목, 왼쪽에 큰 시계, 오른쪽 위에 메모 입력칸이 있다.

### 3.3.1 디자인 (사용자가 요청)
- 보내준 노션 대시보드 사진처럼 **어두운 노션 스타일**(배경 `#191919`, 카드 `#202020`)이다. 위젯도 같은 스타일이다.
- **배너:** 기본 그림은 Claude가 그린 도트 스타일 "한여름 시골 방"이다. 설정에서 사용자가 원하는 사진이나 그림 파일로 바꿀 수 있고, 크기는 작게(160px)/보통(240px)/크게(320px) 중에서 고른다. 기본은 크게다. 사용자가 사진처럼 실사 느낌을 먼저 원했지만 Claude가 실사를 만들 수 없어 도트 그림으로 정했다. 인터넷 사진은 배포하지 않는다.
- **시계:** 큰 시:분:초 타일을 배너 아래에 둔다. 사용자가 유지 여부를 아직 답하지 않았고 Claude가 시안대로 유지하기로 한 부분이다.
- 포스트잇 메모지, 날씨, 빠른 추가 버튼, 목표, 우선순위·상태 열은 사용자가 요청하지 않아 만들지 않는다. 대시보드에는 나중에 카드를 더할 빈 자리를 시안에 두었을 뿐 실제 기능은 없다.

### 3.4 동기화
- 노트북과 데스크톱에서 같은 목록이 보여야 한다.
- 같은 사용자 한 명의 기기끼리만 맞추면 된다.

### 3.5 화면보호기 대시보드 (2단계 기능, 기본 기능 완성 후 추가)
- 자리를 비우면(일정 시간 입력 없음) 전체 화면에 오늘의 대시보드를 보여준다. 사용자가 요청했고, 방법 A(전용 화면보호기)로 정했다.
- **ON/OFF 설정:** 기본값은 OFF이고, 쓰고 싶은 사람만 설정에서 켠다. 켜면 시작 시간(3·5·10·15·30분, 기본 5분), 돌아왔을 때 로그인 요구, 미리 보기 항목이 활성화된다. 끄면 윈도우 기본 화면보호기 설정으로 돌아간다.
- 화면 구성: 큰 시계, 급한 것, 할일, 다가오는 일정, 달력 (시안 "화면보호기 대시보드 시안" 참고).
- 마우스를 움직이거나 아무 키나 누르면 닫힌다. 로그인 요구가 켜져 있으면 윈도우 로그인 화면이 나오고, 꺼져 있으면 바로 바탕화면과 위젯으로 돌아간다.
- 설정 창과 로그인 화면은 시안에서 화면 중앙에 배치한다. (이전 시안에서 좌측 상단으로 붙어 보인 것은 시안의 표시 오류였다.)
- **`Win+L`(윈도우 잠금)은 이 기능과 별개다.** 잠금 화면은 윈도우가 보안상 따로 관리해서 일반 프로그램이 그 위에 화면을 그리거나 키를 가로챌 수 없다. 사용자에게 이 점을 설명했고, 잠금 화면 배경을 일정 그림으로 바꾸는 방법(방법 B)은 보안(로그인 전에 누구나 볼 수 있음)과 안정성 문제로 이번 범위에서 제외했다. 나중에 사용자가 원하면 실험 기능으로 따로 검토한다.
- Claude가 제안한 부분(사용자가 확정하지 않음): 화면보호기에서는 **보기만** 가능하고 체크·입력은 하지 않는다. 화면 잔상을 줄이기 위해 내용 위치를 아주 천천히 움직인다.

## 4. Claude가 정한 부분 (사용자가 직접 정한 게 아님)

- **"일정"과 "할일"의 구분은 Claude의 판단이다.** 시간이 정해진 약속(`내일 3시 회의`)은 일정으로, 마감만 있는 일(`내일까지 견적서`)은 할일(급한 것)으로 저장한다. 애매한 표현은 입력창의 미리보기에서 사용자가 고칠 수 있게 한다. 사용자가 이 기준을 직접 확인한 적은 없다.
- 위젯에서 일정을 뺀 대신, 일정은 대시보드 달력과 일정 카드에서 본다.
- 날짜 표현 해석은 한국어 위주(오늘, 내일, 모레, 다음 주 수요일, 오전/오후, 17시 등)로 시작한다. 인식 못한 표현은 억지로 맞추지 않고 마감 없는 할일로 둔다.

## 6. 데이터 방식 (제안)

- 모든 항목은 하나의 JSON 파일에 저장한다. 항목마다 고유 번호, 내용, 종류(일정/할일), 마감(없을 수 있음), 완료 여부, 수정 시각을 가진다.
- 파일 위치는 사용자가 OneDrive 안에서 정한 폴더(기본값은 설치할 때 안내)이고, 두 기기가 같은 폴더를 가리킨다.
- 파일이 바뀌면 앱이 감지해서 자동으로 다시 읽는다.
- 충돌 방지: 파일 전체를 덮어쓰지 않고 항목 번호 기준으로 병합하며, 같은 항목은 수정 시각이 나중인 쪽을 쓴다. 삭제는 표시만 해 두었다가 일정 기간 뒤에 정리한다.

## 7. 빌더에게 남기는 부분

- 위젯 크기와 색상, 글꼴은 시안 A와 같은 어두운 반투명 느낌으로 시작하고 다듬는다.
- 윈도우 시작 시 자동 실행, 위젯 위치와 크기 기억, 시스템 트레이 아이콘은 합리적인 기본값으로 정한다.
- **설치 파일 제작:** Claude의 작업 환경은 리눅스라 윈도우 설치 파일을 직접 만들 수 없다. 윈도우 빌드를 자동으로 돌려 주는 방법(예: GitHub Actions)을 쓰거나 다른 방법을 찾아서, 사용자가 더블클릭만으로 설치하게 해야 한다. 이 방법은 계획 단계에서 정한다.
- 화면 확인은 윈도우에서 직접 해 볼 수 없으므로, 사용자가 설치해서 보내 주는 피드백으로 보완한다.
- **화면보호기 구현 방식 (2단계):** 윈도우에 진짜 화면보호기(`.scr`)로 등록하는 방식과, 앱이 입력 없음 시간을 감지해 전체 화면 창을 띄우는 방식 중 선택해야 한다. 둘 다 윈도우에서 실제로 동작하는지 확인이 필요하므로 계획 단계에서 정하고, 어느 쪽이든 사용자에게 "화면보호기 ON/OFF"라는 같은 설정으로 보여야 한다.

## 8. 작업 규모

**프로젝트급**이다. 입력창, 위젯, 대시보드, 날짜 해석, 동기화, 설치 파일로 나뉘며, 단계별로 만들어 가며 사용자에게 보여준다.

**단계 구분**
- **1단계 (기본 기능):** 입력창(`Win+J`), 바탕화면 위젯, 대시보드, 날짜 해석, 클라우드 폴더 동기화, 설치 파일
- **2단계 (추가 기능):** 화면보호기 대시보드 (ON/OFF). 1단계를 사용자가 직접 써 본 뒤에 만든다.
